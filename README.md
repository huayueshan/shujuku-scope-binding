# 数据库三层绑定补丁

把通用设置保存一次，让新对话自动继承；有特殊需求的角色单独设置，已有对话保留自己的配置。

数据库 spv9.2.5 本身已按角色保存三个世界书设置，同一角色的不同对话共用；表格模板则有全局默认和对话自己的模板。补丁增加的是它们之间的继承关系：世界书绑定按“已有对话 > 角色 > 全局”应用，角色表格预设可以在新对话缺少模板时与全局合并。

例如全局默认写入“数据库表格专用世界书”，某张角色卡改用“冒险记录”，其中一条对话又可单独改用“支线记录”。修改全局不会把已有对话一并改掉。已有表格模板也不会被自动替换，主动调整用手动合并。

原生规则、适用场景和完整例子见[原生规则与补丁的区别](index.html#why-binding)。

图文入口：[使用指南网页](https://huayueshan.github.io/shujuku-scope-binding/)，也可本地打开 [index.html](index.html)。介绍专用世界书写入、当前世界书读取、角色模板自动合并的用途与步骤。网页不提供下载入口，维护方式见 [Pages 说明](docs/PAGES.md)。

## 功能与边界

- 写入世界书、表格读取世界书、剧情推进世界书和推进预设支持分层绑定。
- 已有对话优先使用自己的绑定；缺少绑定时按角色、全局的顺序继承。
- 普通对话表格模板由数据库原生管理。补丁只在缺少对话模板时补充角色继承，无角色绑定则沿用数据库全局回退。
- 角色填表预设可内嵌并随角色卡导出，可与全局合并，同名表格以角色预设为准。
- 保留手动有序多模板合并，越下方的同名表格优先，通过数据库公开 API 完成迁移。
- 提供手动清空并更新写入世界书；运行中重复点击不会并发启动另一轮。
- 数据库定位使用公开 API 的所属运行环境，不依赖数据库安装 UUID、脚本名称或特定用户地址。

## 使用入口

安装前备份角色卡、聊天和世界书。
加载酒馆助手、数据库和补丁后，从扩展程序菜单打开“数据库三层绑定”。
在各功能中选择全局或角色等作用域，选择目标后点击绑定按钮；普通对话表格模板请进入数据库填表工作台。
手动合并可能改变当前对话表结构，应用前确认来源、顺序及数据库迁移结果。

已有安装升级必须保留补丁 ID 以及用户的 `data`、启停和按钮配置，不要用发行 JSON 的空 `data` 覆盖现有数据。
避免在持有旧设置的多个页面中同时编辑脚本。操作步骤见[使用与升级](docs/USAGE.md)。

## 构建与测试

使用 Node.js 22 或更高版本，无第三方构建依赖：

```sh
node scripts/build-release.mjs
node --check patches/shujuku-scope-binding-patch.js
node --experimental-vm-modules --test tests/*.test.mjs
```

归档验收另需 PowerShell 7；相关自动测试在未安装 PowerShell 时明确跳过，不计作通过。
`pwsh -File scripts/package-release.ps1 -ValidateOnly` 会在内存中压缩、解压并核验白名单和哈希，不输出 ZIP、不联网。
不带该参数才会生成 ZIP，且许可证未确认时拒绝输出。构建与验收均不执行 Git 提交或发布。

生成文件为根目录的“酒馆助手脚本-数据库三层绑定补丁.json”，其中包含完整补丁源码。
“离线版”指补丁源码随 JSON 携带，不代表酒馆助手和数据库的其他依赖完全无需网络。

v1.7.11 的基本测试覆盖 spv8.9.2、spv9.1、spv9.1.6、spv9.2.3 和 spv9.2.5；本轮实机使用 spv9.2.5。spv8.4 保留 v1.7.10 的历史记录，不冒充本轮验收。
每个发行版本的确切对应关系、验证等级和限制见[兼容性版本表](COMPATIBILITY.md)及[机器可读映射](compatibility.json)。
发行仓库的测试只包含可独立运行的产品回归，不内置上游源码快照或私人部署测试。
不宣称已经实测每一个中间版本或未来版本。
