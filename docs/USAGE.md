# 使用与升级

## 三种交付方式

正式发行必须分别提供以下三个可直接导入酒馆助手的 JSON；JS 源码和 ZIP 仅作为配套资产，不替代 JSON。

| 文件 | 行为 | 使用建议 |
| --- | --- | --- |
| `dist/offline.json` | 包含完整补丁源码 | 不想在补丁启动时访问 CDN |
| `dist/online-fixed.json` | 加载 v1.7.10 的固定代码 | 日常稳定使用 |
| `dist/online-latest.json` | 加载 jsDelivr 解析的最新语义化版本 | 愿意接受后续行为变化 |

三个 JSON 的脚本 UUID 相同，只安装一个。不要把“离线版”误认为整个酒馆及其他依赖都无需网络。
正式发布前，在线 URL 只是待发布配置；不要通过当前尚未发布的链接判断安装成败。

两个在线 JSON 沿用数据库本体的加载思路：脚本正文用 `import '远程 JS 地址'` 加载模块。固定版锁定 release 标签，latest 使用最新语义化版本别名；二者不是只发一条 URL，也不需要用户手工新建脚本。

## 首次安装

1. 安装 SillyTavern、酒馆助手和 shujuku 数据库；对照本包的[兼容性表](../COMPATIBILITY.md)。
2. 备份聊天、角色、世界书和现有脚本设置。在酒馆助手全局脚本库中确认没有已经安装的“数据库三层绑定补丁”。
3. 选择一种 JSON，通过酒馆助手导入一次并启用。导入后检查同名脚本只存在一个；若存在重复项，先停止操作并检查来源，不盲目再次导入。
4. 打开一条已有对话，在扩展程序菜单点击“数据库三层绑定”。等待面板完成读取，检查当前生效、来源与核验结果。首页没有有效对话时不能据此判断对话绑定是否正常。

酒馆助手 4.8.19 实测会在首次导入时重新生成脚本 ID，并默认关闭脚本。这不代表文件损坏；启用后可以正常运行。以后升级应定位这份实际安装的脚本并保留其 ID，不能假定导入后的 ID 一定等于发行 JSON 中的 ID。

## 绑定和继承

在对应功能行选择“全局”或“角色”等作用域，选择目标后点击链接图标保存；断链图标用于解除该层绑定。切换作用域只查看或编辑该层，不等于已经保存新绑定。
下拉列表打开后，菜单顶部提供搜索过滤。手动读取世界书时，旁边的列表按钮打开世界书和条目选择器。

已有对话优先使用自身快照；缺少快照时按角色、全局的顺序继承。因此修改全局并不会强制改写所有旧对话。
普通对话表格模板以数据库自身状态为准，点击“在数据库中管理对话模板”进入填表工作台。

角色表格模板可绑定全局预设，也可绑定内嵌预设；开启“合并当前全局模板”后，同名表格以角色预设为准。
内嵌复制会形成独立副本，之后修改全局原件不自动更新内嵌副本。导出卡片会包含角色变量，分享前自行检查内嵌内容是否包含个人信息。
制卡格式见[内嵌标准](../analysis/character-embedded-table-preset-standard.md)。

## 手动合并和世界书同步

### 专用写入世界书：先加入全局，再绑定写入

1. 在酒馆世界书界面新建空白书，例如“数据库表格专用世界书”。
2. **把它加入酒馆的全局世界书。** 正文生成才会按条目的启用和触发规则读取其中的表格内容。
3. 在补丁“写入世界书”一行选择“全局”和这本书，再点击链接图标保存。

酒馆的“全局世界书”和补丁的“全局写入绑定”不是同一个设置：前者负责让正文读取，后者决定数据库写到哪里。补丁不会因为保存了全局写入绑定就自动把这本书加入全局世界书，两个步骤都要做。

“重新应用到当前对话”是显式迁移操作：选择全局或内嵌来源并排列顺序，越下方的同名表格优先。确认后由数据库公开 API 处理迁移；操作前备份，不能把它当成无副作用预览。

底部“清空并更新写入世界书”用于手动修复同步。运行期间重复点击不会启动并发任务；切换或关闭对话会使旧上下文任务失效。仍在等待数据库初始化时先查看状态，不反复点击。

## 已有安装升级

不要反复用导入按钮覆盖已有安装：部分酒馆助手版本会产生新的脚本 ID 或同名副本。
备份后，关闭旧页面或刷新唯一维护页面，使用当前酒馆助手版本支持的原位脚本更新能力；精确定位现有脚本，保留现有 `data`、启停、按钮状态及脚本身份，只更换本次需要更新的代码/说明。
不要整体保存旧页面持有的全局设置，不要把发行文件中的空 `data` 写入已有脚本，也不要删除再重新添加以绕过冲突。
如果自己的维护方式不能确保这些条件，先在副本环境验证，不在真实聊天上试错。

更新固定在线版需切换到新版本对应的加载代码；latest 则在脚本重新加载时请求 CDN，但不保证立即得到刚发布的新版本。
回退时选择上一版固定版并保留用户数据；新版已经迁移过的数据未必可直接降级，优先恢复备份。

## latest 与缓存

本包使用 `https://cdn.jsdelivr.net/gh/huayueshan/shujuku-scope-binding@latest/dist/index.js`。
jsDelivr 按有效语义化标签解析 latest；没有标签时可能回退默认分支，因此首次发布必须同时建立正式标签后才宣传在线入口。
固定版本文件可能被长期缓存，发布后不能覆盖同名 tag 修复代码；应发布新版本。latest 别名也有缓存，故“最新”不是实时更新保证。
详见 [jsDelivr 官方说明](https://github.com/jsdelivr/jsdelivr#github)。

## 国内网络

jsDelivr 官方说明其采用多 CDN 调度和靠近中国的节点网络，但这不构成所有地区、运营商和时段的速度保证，见[网络说明](https://www.jsdelivr.com/network)。当前没有覆盖国内多运营商的测速证据，不能宣称稳定秒开。
使用离线 JSON 可以避免补丁本身启动时依赖 CDN。固定在线与 latest 的差别是版本选择，不代表某一种一定更快；未实测前也不宣称固定到某个 CDN 提供商域名能改善所有人的访问。

## 安全反馈

只提供补丁版本、数据库版本、复现步骤以及脱敏后的错误摘要。不要直接公开 `diagnose()`、`getState()`、`getCharacterData()` 的完整输出或自己的角色卡、聊天、世界书内容。
本包不附私人实机截图；公开演示应使用独立合成数据，不把遮挡部分文字等同于整张截图已完成脱敏。
